# Data pipeline

Everything that puts places and toilets into the database lives in `src/imports/` and runs via the
CLI `pnpm cli <command> [flags]` (`src/cli.ts`, framework-free, Prisma via `@prisma/adapter-pg`,
connection string from `DIRECT_URL ?? DATABASE_URL`). Every command that writes to the DB records an
`ImportRun` row (source, command, inserted/updated/skipped counts, `log` JSON incl. attribution).

```
data/
  raw/                      committed downloads (reproducible input)
    sheet/*.csv             fieldwork Google Sheet tabs (March 2024 pilot)
    survey-2024b/*.csv      expanded survey tabs (Aug-Oct 2024): raw-data.csv, location-index.csv
    geocode-cache/onemap/   OneMap search responses, one file per query
    datagov/*.geojson       data.gov.sg datasets
    osm/toilets.json        Overpass snapshot (sorted elements)
    wikidata/stations.json  processed SPARQL result (Singapore stations)
  curated/                  generated + hand-edited inputs to the DB seed
    fieldwork-2024.json     GENERATED by sheet:normalise (venues, toilets, features, surveys)
    fieldwork-2024b.json    GENERATED by survey2:normalise (expanded survey: venues, toilets, features, surveys)
    survey2-venue-matches.json  GENERATED by survey2:match, HAND-EDITABLE ("locked": true entries are kept)
    venues.geocoded.json    GENERATED by geocode (lat/lng, address, planning area per pilot venue key)
    survey2-venues.geocoded.json  GENERATED by geocode (same, per survey2 Location Code)
    review.json             GENERATED: rows needing / having had human attention
    overrides.json          HAND-EDITED geocode fixes (applied last; pilot venue keys and survey2 codes) and survey2 remarkOverrides
    enrichment.csv          HAND-EDITED extra facts per toilet (applied with source ADMIN)
```

`pnpm db:seed` (`prisma/seed.ts`) is the offline subset: `enrich` check + `seed:fieldwork` +
`seed:fieldwork-2024b` from the committed curated files + score recompute. It never touches the network.

Typical refresh of the fieldwork data: `pnpm cli sheet:fetch && pnpm cli sheet:normalise && pnpm cli geocode`,
eyeball the table / `review.json`, fix `overrides.json`, re-run `geocode`, commit `data/`, then `pnpm db:seed`.
Expanded survey: `pnpm cli survey2:fetch && pnpm cli survey2:normalise && pnpm cli survey2:match && pnpm cli geocode &&
pnpm cli survey2:match` (the second match adds OSM matches and distances), review `survey2-venue-matches.json`, the
tables and `review.json` (`survey2*` sections), lock any corrections, then `pnpm cli seed:fieldwork-2024b`.
Scheduled jobs: `pnpm cli import:osm` (weekly), `pnpm cli import:datagov --dataset all` and
`pnpm cli import:wikidata` (monthly).

## How the sheet is interpreted (`sheet:normalise`)

- **Location parsing**: trailing `L3`/`B1` → `Toilet.level`; line codes (NSL EWL NEL CCL DTL TEL, any
  separator) → `lines`; text after the last code (`Linkway`) marks a separate toilet at the same venue.
- **One venue per physical place**: same type + same parsed name → one venue (e.g. Outram Park EWL/NEL/TEL →
  venue "Outram Park" with 3 toilets "EWL side"/"NEL side"/"TEL side"). Labels are only set when a venue has
  several toilets or serves lines the toilet does not.
- **Survey** per toilet from General Data: `rubric=PILOT_50`, `sex=MALE` (UNISEX for the handicapped-only
  stations), cleanliness, scent, aesthetics, music, toiletries (sum of 5), facilities (sum of 16), total (sheet
  value), `rasStars` from RAS Ratings (1–5 only), remarks, `breakdown` null, `raw` = every column. `surveyedAt`
  2024-03-15.
- **Features** (`FIELDWORK_2024`, observed 2024-03-15): value > 0 → present for Toilet Paper, Hand Towel, Hand
  Dryer, Hand Soap, Toilet Liner (SEAT_LINER), Coat Hooks, Bidet, Auto Flush/Tap/Soap, Feedback, Ambulant,
  Child, Signages, Posters. Mirror/Taps/Urinals/Toilets/Door Locks/Bin stay in the survey. All → FREE; MRT,
  mall and bus-interchange → SITTING. Remark "No M/F toilet, only 1 handicapped" (and the Miscellaneous
  handicapped-only list) → MALE=false, FEMALE=false, ACCESSIBLE=true, UNISEX=true. Every other surveyed toilet
  → MALE=true (the pilot looked at men's toilets only); renovation-only placeholders get no sex feature.
- **Toilet Renewal**: pre-renewal rows → extra survey `phase="pre-renewal"` dated 2024-03-14; post-renewal
  rows identical to the General Data row tag that survey `phase="post-renewal"` (no duplicate). "Under
  Renewal" stations → `needsResurvey=true`; stations without a General Data row get a toilet with
  `status=RENOVATION`, no survey.
- **Miscellaneous**: "Stations without Toilets" → `toiletStatus=NONE` only when the whole venue has no toilet
  (Changi Airport); otherwise the venue stays HAS_TOILETS and `note` records the gap ("No toilet on the CCL
  side", Bishan/Dhoby Ghaut/Marina Bay CCL, Expo EWL). "Uses …" stations → `USES_NEARBY` + note (Toa Payoh,
  Novena, Somerset); Orchard NSL "toilet inside Orchard Exchange" stays HAS_TOILETS because Orchard TEL has a
  surveyed toilet — the NSL remark is in the note. `externalIds.usesNearbyVenueSourceKey` links Toa Payoh → HDB Hub.
- **Opening hours** (all `inferred: true`): MRT & bus interchanges Mon–Sat 05:30–00:30, Sun 06:00–00:30;
  malls 10:00–22:00; hawker 06:00–22:00; coffee shops 06:00–23:00; CC 09:00–22:00. Toilets inherit (null).

## How the expanded survey is interpreted (`survey2:normalise`, `survey2:match`, `seed:fieldwork-2024b`)

- **Rows**: one Survey per Raw Data row (`rubric=EXPANDED_2024`, `sex` from the row, `surveyedAt` = the row
  timestamp read as Singapore time, `cleanliness = (c + 3) / 6 * 10`, pilot columns null, `breakdown` as in the
  table below). Checklist cells are split against the known item lists (items contain commas); text that is not an
  item ("Others") becomes `remarks` (toiletries/facilities leftovers are prefixed). `raw` keeps every column under
  short names (`Timestamp`, `Sector`, `Sex`, `Location Code`, `Location within premise`, `Cleanliness`, `Reasons`,
  `Scent`, `Toiletries`, `Facilities`, `Photo`) plus `_tab`, `_row`, `_key`, `_source`.
- **Retractions**: a row whose free text says "ignore previous response" (Raw Data row 20, H86) takes back the row
  before it. That row is not imported when it is unambiguous: the only earlier row of the same code and sex from the
  same team (Sector) within 15 minutes. Otherwise every row is imported and review.json (`survey2`,
  `survey2-retraction`) lists the candidates. The note itself is never shown (not in `accessNote`, not in `remarks`).
  Row 20 is a women's row and no earlier women's H86 row exists (rows 8 and 13 are men's, same team), so it stays
  flagged.
- **Remarks**: review.json `survey2Remarks` lists every survey with a free-text remark (survey key, toilet, venue,
  sex, remark) to read in one place. `overrides.json` `remarkOverrides` replaces one (string) or blanks it (null),
  keyed by survey key; `survey2:normalise` applies it and the list shows the sheet's text as `original`. Features
  are still read from the sheet's text (a blanked "No sanitary bin" still records SANITARY_BIN absent).
- **Codes**: `M6.` is read as `M6`. Prefix → type: `NS EW NE CC CE DT TE` MRT (lines NSL EWL NEL CCL CCL DTL TEL),
  `M` mall, `C` coffeeshop, `H` hawker centre, `B` bus interchange. A station venue's lines are every line the index
  lists for that station name (City Hall EW13 → EWL, NSL).
- **Names**: stations by the premise minus line codes; malls / hawkers / interchanges by the premise ("(renamed X)" →
  X, all-caps title-cased; nicer names via `overrides.json` `name`); address-only coffeeshops "Coffeeshop, Blk 103
  Gangsa Road" ("Blk" only with an HDB unit number; several in one block get the unit: "(#01-93)"). Venue address
  and postcode come from the index.
- **Toilets**: one per (code, sex). Label "Men's" / "Women's" / "Accessible / unisex", plus the line side at a
  multi-line station ("Women's, NEL side") and wing/lobby/tower/exit words ("Men's, West Wing"). The free-text
  location gives `level` (Level 3, L3, B1, Basement 1, Ground, Level Two …, normalised by `levelFields`) and the rest,
  minus a repeated premise name, becomes `accessNote`. Tier VERIFIED, `lastVerifiedAt` = the row timestamp.
- **Features** (`FIELDWORK_2024_EXPANDED`, observed at the row timestamp; ticked = present, unticked = absent):
  TOILET_PAPER HAND_TOWEL HAND_DRYER HAND_SOAP SEAT_LINER BIDET AUTO_FLUSH AUTO_TAP AUTO_SOAP FEEDBACK_DEVICE AMBULANT
  CHILD NURSING_ROOM ACCESSIBLE ("Handicapped Facilities Available") MIRROR ("Mirrors functional"); MALE / FEMALE /
  UNISEX from the row's sex. SANITARY_BIN = present when the "[Female] Sanitary bin …" reason is ticked; absent only
  when a women's row says there is none ("No sanitary bin"), otherwise unset (not ticking it may just mean it was
  dirty). Taps / urinals / toilets / door locks functional and "Rubbish bin not full" stay in the survey only.
- **Venue matching** (`survey2:match`), first hit wins: pilot venue of the same type by name (station names exactly;
  others by name or every word of the shorter name, incl. the pilot's override name and OneMap match; coffeeshops also
  by postcode) → Wikidata station by code, else by name → data.gov.sg hawker centre by postcode, else by name → OSM
  `toilets=yes` venue of the same type within 60 m of our geocode with a similar name. A match further than 400 m from
  our geocode, or by a weaker rule, is listed in review.json. The seed resolves a match by `sourceKey`, else through
  the link the other importer left (`externalIds.wikidata`, `externalIds.datagov.hawker`, `externalIds.osm`); a match
  not in the DB yet (fresh DB before those imports) gets a `survey2-venue:` venue at our geocode instead.
- **Rows on pilot toilets**: at a matched pilot venue, a row whose sex the pilot saw there (men's; unisex at the 3
  handicapped-only stations) is another survey of the pilot toilet when: at a station, the pilot toilet on the
  code's line (EW16 → `sheet:outram-park-ewl`); elsewhere, the only pilot toilet, on the same level when the pilot
  recorded one. Several such rows at one code: the ones that name no location are taken to be the pilot toilet,
  the rest are new toilets. Anything else is a new toilet, listed in review.json. The seed then adds the survey,
  replaces pilot features with the newer observation, moves `lastVerifiedAt` forward and sets a pilot RENOVATION
  placeholder to ACTIVE (it was surveyed in use). It never changes the pilot toilet's label, level or needsResurvey.
- **Reused venues** only get `toiletStatus=HAS_TOILETS`, `externalIds.survey2Codes` and (stations) a union of lines;
  new toilets there take the venue's coordinates.
- **Photos**: the Drive links stay in `fieldwork-2024b.json` (`photoUrl`); see `survey2:photos`.

## Provenance and merge rules

- `ToiletFeature` rows with source `COMMUNITY` or `ADMIN` are never overwritten by an import; OSM additionally
  never overwrites either fieldwork source (`FIELDWORK_2024`, `FIELDWORK_2024_EXPANDED`), and the pilot seed
  never overwrites `FIELDWORK_2024_EXPANDED` (newer observation wins); the expanded seed replaces a
  `FIELDWORK_2024` row only when its own observation is newer (`planFeature(..., newerWins)`). Enrichment (`ADMIN`)
  overwrites anything.
- Re-seeding fieldwork only fills toilet fields that are empty (label, level, areaType UNKNOWN, …) so later
  human corrections survive; enrichment values win; `status` is set on create only; `needsResurvey` is never
  reset; `lastVerifiedAt` only moves forward. Venue `lines` are unioned; `address` is kept once set unless
  `overrides.json` gives one.
- **OSM**: `access=private|no` skipped; `customers`/`passengers`/`permit` → `accessNote`. Tag map: wheelchair
  (or toilets:wheelchair) yes|designated/no → ACCESSIBLE; fee no/yes → FREE true/false; changing_table →
  BABY_CHANGE; toilets:position seated/squat → SITTING/SQUAT; male/female/unisex; soap only if
  `toilets:handwashing:soap`/`soap` is tagged; shower → SHOWER; toilets:paper_supplied → TOILET_PAPER;
  toilets:hands_drying → HAND_DRYER/HAND_TOWEL; level:ref ?? addr:floor ?? level → level; opening_hours →
  `{type:'osm'}` (`24/7` → always). Venue: an existing venue within 60 m (prefer similar name; never a
  NONE/USES_NEARBY venue; a `toilets=yes` shop needs a name match) else a new `osm-venue:` venue. **Dedupe**:
  skip an OSM toilet if a FIELDWORK/COMMUNITY toilet at the same venue is within 40 m (listed in
  `ImportRun.log.deduped`); that includes the toilet's own `osm-venue:` venue, and an OSM toilet whose own venue
  is already in the DB goes back to it. `seed:fieldwork-2024b` applies the same rule the other way round: an
  ACTIVE OSM toilet at a venue with survey2 toilets, within 40 m of one, is deleted unless it has reviews, check-ins,
  photos, status reports, flags, submissions or COMMUNITY/ADMIN features (`ImportRun.log.osmSuperseded` /
  `osmKeptInUse`, both keys each); import:osm then dedupes it instead of re-adding it. Re-runs keep an imported toilet's venue. OSM toilets that vanish → CLOSED unless
  they have COMMUNITY/ADMIN features or submissions (and only if the new snapshot has ≥ 50 % of the old count).
- **data.gov.sg**: a dataset point links to an existing venue of the same type within 60 m (or 300 m with a
  similar name), or to a generic OSM toilet venue there (which then takes the dataset's name/type — e.g. a
  "Public toilet" node at a hawker centre becomes that hawker centre); hawker centres also link through any
  toilet within 60 m. Links are recorded in `externalIds.datagov.<dataset> = [ids]`; NEA's address replaces the
  linked venue's address. Otherwise a shell venue with `toiletStatus=UNKNOWN` is created. Hawker centres
  "Under Construction" are skipped; NParks playgrounds / open spaces / fitness corners (names ending PG, OS,
  FC, …) are skipped (they rarely have toilets). MRT exits are matched by station name (or by Wikidata
  station code for exits listed by code, e.g. "CC31") and stored as `externalIds.exits = [{exit, lat, lng}]`.
- **Wikidata**: a station is "in use" when P5817 = in use (or no state, an opening date in the past and not
  "former"). Same-name MRT venues within 1.5 km are linked (`externalIds.wikidata`, `externalIds.codes`).

## Survey rows (rubric-agnostic)

`Survey.rubric` says which score sheet a row uses. `Survey.cleanliness` is always 0–10 and is what feeds
`blendCleanliness`; `sex` is the toilet the surveyor looked at.

| Rubric | Columns | `breakdown` |
|---|---|---|
| `PILOT_50` | scent, aesthetics, music, toiletries 0–5; facilities 0–20; total /50 | null |
| `EXPANDED_2024` | pilot columns null; cleanliness = `(c + 3) / 6 * 10` | `{ cleanliness: −3..3, scent: −2..2, reasons: string[], toiletries: string[], facilities: string[] }`, item text verbatim from the lists in `src/toilets/survey-items.ts` (6 reasons, 5 toiletries, 15 facilities; never "None of the Above"; "Others" free text goes in `remarks`) |

## overrides.json

```json
{ "<venue key>": { "query": "OneMap query to use", "pick": "substring SEARCHVAL/ADDRESS must contain",
                   "lat": 1.3, "lng": 103.8, "name": "Display name", "address": "...", "postalCode": "...",
                   "reason": "why" } }
```
All fields optional; lat/lng replace the geocode entirely. Re-run `pnpm cli geocode` after editing.

One more top-level key, `remarkOverrides`, is not a venue: survey key (as in review.json `survey2Remarks`) →
the remark to show instead, or `null` to blank it. Re-run `pnpm cli survey2:normalise` and `seed:fieldwork-2024b`
after editing.
```json
{ "remarkOverrides": { "survey2:H85/female#2024-08-24T09:23:29+08:00": null } }
```
