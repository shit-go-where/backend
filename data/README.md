# Data pipeline

Everything that puts places and toilets into the database lives in `src/imports/` and runs via the
CLI `pnpm cli <command> [flags]` (`src/cli.ts`, framework-free, Prisma via `@prisma/adapter-pg`,
connection string from `DIRECT_URL ?? DATABASE_URL`). Every command that writes to the DB records an
`ImportRun` row (source, command, inserted/updated/skipped counts, `log` JSON incl. attribution).

```
data/
  raw/                      committed downloads (reproducible input)
    sheet/*.csv             fieldwork Google Sheet tabs
    geocode-cache/onemap/   OneMap search responses, one file per query
    datagov/*.geojson       data.gov.sg datasets
    osm/toilets.json        Overpass snapshot (sorted elements)
    wikidata/stations.json  processed SPARQL result (Singapore stations)
  curated/                  generated + hand-edited inputs to the DB seed
    fieldwork-2024.json     GENERATED by sheet:normalise (venues, toilets, features, surveys)
    venues.geocoded.json    GENERATED by geocode (lat/lng, address, planning area per venue key)
    review.json             GENERATED: rows needing / having had human attention
    overrides.json          HAND-EDITED geocode fixes (applied last)
    enrichment.csv          HAND-EDITED extra facts per toilet (applied with source ADMIN)
```

## Commands

| Command | What it does | Network |
|---|---|---|
| `sheet:fetch` | Downloads the 5 tabs of Google Sheet `1nMJffy4cIbJwKaiI--LgnsdksrTStu-bGiybAxtYqww` to `raw/sheet/` via `export?format=csv&gid=<gid>` (gids: Rubrics 0, General Data 1534707311, RAS Ratings 1650716793, Toilet Renewal 812045906, "Miscellaneous " 2088377781). We use the per-gid export, not gviz: gviz merges the two header rows into one ("Toiletries (5) Toilet Paper (1)"). | yes |
| `sheet:normalise` | `raw/sheet/*.csv` → `curated/fieldwork-2024.json` + `review.json` (`normalise` section). Pure, deterministic. | no |
| `geocode` | Geocodes every curated venue → `curated/venues.geocoded.json`, assigns planning areas, writes `review.json` (`geocode` section) and prints a review table. Only queries OneMap for queries not in `raw/geocode-cache` (`--refresh` re-queries, `--offline` forbids network). Fails if any venue is unresolved. | cache misses |
| `enrich` | Validates `curated/enrichment.csv`. (Applied by `seed:fieldwork`.) | no |
| `seed:fieldwork` | Upserts curated venues → toilets → features → surveys by `sourceKey`, applies enrichment (ADMIN), then `recompute-scores`. Idempotent. | no |
| `import:osm` | Overpass → `raw/osm/toilets.json` → OSM toilets/venues. `--cached`/`--offline` use the committed snapshot, `--no-close` disables closing vanished toilets. | yes by default |
| `import:datagov --dataset hawker\|mrt-exits\|cc\|parks\|libraries\|all` | data.gov.sg datasets → venue shells / exits. A dataset that cannot be downloaded is logged and skipped. `--cached`/`--offline` use `raw/datagov/`. | yes by default |
| `import:wikidata` | Adds in-use MRT/LRT stations missing from the DB; links existing ones (Q-ids, station codes), fills empty `lines`. `--cached`/`--offline`. | yes by default |
| `recompute-scores` | `recomputeAllScores` from `src/toilets/scoring.ts`. | no |
| `all` | `sheet:normalise`, `geocode`, `enrich`, `seed:fieldwork`, `import:osm`, `import:wikidata`, `import:datagov --dataset all`, `recompute-scores` — from the committed raw files by default (reproducible). `--refresh` re-downloads OSM/data.gov.sg/Wikidata (geocode always stays on its cache). `import:wikidata` runs before `import:datagov` so new stations get their LTA exits in the same pass. | only with `--refresh` (or cache misses) |

`pnpm db:seed` (`prisma/seed.ts`) is the offline subset: `enrich` check + `seed:fieldwork` from the
committed curated files + score recompute. It never touches the network.

Typical refresh of the fieldwork data: `pnpm cli sheet:fetch && pnpm cli sheet:normalise && pnpm cli geocode`,
eyeball the table / `review.json`, fix `overrides.json`, re-run `geocode`, commit `data/`, then `pnpm db:seed`.
Scheduled jobs: `pnpm cli import:osm` (weekly), `pnpm cli import:datagov --dataset all` and
`pnpm cli import:wikidata` (monthly).

## Keys (stable, used for idempotent upserts)

| Record | `sourceKey` |
|---|---|
| fieldwork toilet | `sheet:<slug of the Location cell>` e.g. `sheet:outram-park-ewl`, `sheet:harbourfront-ccl-nel`, `sheet:marina-bay-tel-linkway`, `sheet:jewel-l3`; renovation-only stations `sheet:bukit-batok`, `sheet:tampines-ewl` |
| fieldwork venue | `sheet-venue:<type prefix>-<slug of venue name>` e.g. `sheet-venue:mrt-outram-park`, `sheet-venue:mall-jewel`, `sheet-venue:hc-chong-pang` (prefixes mrt, mall, bi, hc, cs, cc). The part after the colon is the "venue key" used in `venues.geocoded.json` / `overrides.json`. |
| OSM toilet / venue | `osm:<node\|way>/<id>` / `osm-venue:<node\|way>/<id>` |
| data.gov.sg venue | `datagov-<dataset>:<slug of NAME>` (e.g. `datagov-hawker:tiong-bahru-market`) |
| Wikidata station | `wikidata:<Q-id>` |
| fieldwork survey | no column; `Survey.raw._key = "<toilet sourceKey>#<phase or general>#<date>"`, `raw._source = "FIELDWORK_2024"` |

Slugs: lowercase ASCII, `&`→and, `@`→at, everything else non-alphanumeric → `-`.

## How the sheet is interpreted (`sheet:normalise`)

- **Location parsing**: trailing `L3`/`B1` → `Toilet.level`; line codes (NSL EWL NEL CCL DTL TEL, any
  separator) → `lines`; text after the last code (`Linkway`) marks a separate toilet at the same venue.
- **One venue per physical place**: same type + same parsed name → one venue (e.g. Outram Park EWL/NEL/TEL →
  venue "Outram Park" with 3 toilets "EWL side"/"NEL side"/"TEL side"). Labels are only set when a venue has
  several toilets or serves lines the toilet does not.
- **Survey** per toilet from General Data: cleanliness, scent, aesthetics, music, toiletries (sum of 5),
  facilities (sum of 16), total (sheet value), `rasStars` from RAS Ratings (1–5 only), remarks, `raw` = every
  column. `surveyedAt` 2024-03-15.
- **Features** (`FIELDWORK_2024`, observed 2024-03-15): value > 0 → present for Toilet Paper, Hand Towel, Hand
  Dryer, Hand Soap, Toilet Liner (SEAT_LINER), Coat Hooks, Bidet, Auto Flush/Tap/Soap, Feedback, Ambulant,
  Child, Signages, Posters. Mirror/Taps/Urinals/Toilets/Door Locks/Bin stay in the survey. All → FREE; MRT,
  mall and bus-interchange → SITTING. Remark "No M/F toilet, only 1 handicapped" (and the Miscellaneous
  handicapped-only list) → MALE=false, FEMALE=false, ACCESSIBLE=true, UNISEX=true.
- **Toilet Renewal**: pre-renewal rows → extra survey `phase="pre-renewal"` dated 2024-03-14; post-renewal
  rows identical to the General Data row tag that survey `phase="post-renewal"` (no duplicate). "Under
  Renewal" stations → `needsResurvey=true`; stations without a General Data row get a toilet with
  `status=RENOVATION`, no survey.
- **Miscellaneous**: "Stations without Toilets" → `toiletStatus=NONE` only when the whole venue has no toilet
  (Changi Airport); otherwise the venue stays HAS_TOILETS and `note` records the gap ("No toilet on the CCL
  side", Bishan/Dhoby Ghaut/Marina Bay CCL, Expo EWL). "Uses …" stations → `USES_NEARBY` + note (Toa Payoh,
  Novena, Somerset); Orchard NSL "toilet inside Orchard Exchange" stays HAS_TOILETS because Orchard TEL has a
  surveyed toilet — the NSL remark is in the note. `externalIds.usesNearbyVenueSourceKey` links Toa Payoh → HDB Hub.
- **Opening hours** (all `inferred: true`): MRT & bus interchanges Mon–Sat 05:30–00:30, Sun 06:00–00:30;
  malls 10:00–22:00; hawker 06:00–22:00; coffee shops 06:00–23:00; CC 09:00–22:00. Toilets inherit (null).

## Provenance and merge rules

- `ToiletFeature` rows with source `COMMUNITY` or `ADMIN` are never overwritten by an import; OSM additionally
  never overwrites `FIELDWORK_2024`. Enrichment (`ADMIN`) overwrites anything.
- Re-seeding fieldwork only fills toilet fields that are empty (label, level, areaType UNKNOWN, …) so later
  human corrections survive; enrichment values win; `status` is set on create only; `needsResurvey` is never
  reset; `lastVerifiedAt` only moves forward. Venue `lines` are unioned; `address` is kept once set unless
  `overrides.json` gives one.
- **OSM**: `access=private|no` skipped; `customers`/`passengers`/`permit` → `accessNote`. Tag map: wheelchair
  (or toilets:wheelchair) yes|designated/no → ACCESSIBLE; fee no/yes → FREE true/false; changing_table →
  BABY_CHANGE; toilets:position seated/squat → SITTING/SQUAT; male/female/unisex; soap only if
  `toilets:handwashing:soap`/`soap` is tagged; shower → SHOWER; toilets:paper_supplied → TOILET_PAPER;
  toilets:hands_drying → HAND_DRYER/HAND_TOWEL; level:ref ?? addr:floor ?? level → level; opening_hours →
  `{type:'osm'}` (`24/7` → always). Venue: an existing venue within 60 m (prefer similar name; never a
  NONE/USES_NEARBY venue; a `toilets=yes` shop needs a name match) else a new `osm-venue:` venue. **Dedupe**:
  skip an OSM toilet if a FIELDWORK/COMMUNITY toilet at the same venue is within 40 m (listed in
  `ImportRun.log.deduped`). Re-runs keep an imported toilet's venue. OSM toilets that vanish → CLOSED unless
  they have COMMUNITY/ADMIN features or submissions (and only if the new snapshot has ≥ 50 % of the old count).
- **data.gov.sg**: a dataset point links to an existing venue of the same type within 60 m (or 300 m with a
  similar name), or to a generic OSM toilet venue there (which then takes the dataset's name/type — e.g. a
  "Public toilet" node at a hawker centre becomes that hawker centre); hawker centres also link through any
  toilet within 60 m. Links are recorded in `externalIds.datagov.<dataset> = [ids]`; NEA's address replaces the
  linked venue's address. Otherwise a shell venue with `toiletStatus=UNKNOWN` is created. Hawker centres
  "Under Construction" are skipped; NParks playgrounds / open spaces / fitness corners (names ending PG, OS,
  FC, …) are skipped (they rarely have toilets). MRT exits are matched by station name (or by Wikidata
  station code for exits listed by code, e.g. "CC31") and stored as `externalIds.exits = [{exit, lat, lng}]`.
- **Wikidata**: a station is "in use" when P5817 = in use (or no state, an opening date in the past and not
  "former"). Same-name MRT venues within 1.5 km are linked (`externalIds.wikidata`, `externalIds.codes`).

## overrides.json

```json
{ "<venue key>": { "query": "OneMap query to use", "pick": "substring SEARCHVAL/ADDRESS must contain",
                   "lat": 1.3, "lng": 103.8, "name": "Display name", "address": "...", "postalCode": "...",
                   "reason": "why" } }
```
All fields optional; lat/lng replace the geocode entirely. Re-run `pnpm cli geocode` after editing.

## enrichment.csv

Header: `sourceKey,areaType,level,nearestExit,male,female,accessible,sitting,squat,babyChange,notes`.
`areaType` ∈ PAID_AREA, UNPAID_AREA, NOT_APPLICABLE, UNKNOWN; booleans yes/no/true/false/1/0 or blank
(= no opinion); `notes` → `Toilet.accessNote`. Any toilet `sourceKey` works (sheet or OSM). Applied by
`seed:fieldwork` / `pnpm db:seed` with source ADMIN.
